# 매일 말씀: 개인별 읽기 기록 동기화 설계

## 현재 구현 (2026-10-25)
- GitHub Pages 정적 웹앱, 5개 트랙
- 각 트랙 첫 회차(총 5편) 공개 체험 원고
- 목록 · 이전/다음 · 이어 읽기 · 읽음 표시 · 즐겨찾기
- 기기 브라우저 localStorage 프로필별 데이터
- JSON 파일로 백업/복원, 다른 기기로 읽기 기록 옮기기
- 공식 Sheets DailySchedule 변경 없음; PUBLISHED=0

## 중요한 한계
localStorage는 기기별/브라우저별 저장소입니다. 같은 프로필 이름을 두 기기에서 사용해도 자동 동기화되지 않습니다. 현재 프로필은 로그인 계정이 아니므로 신원 확인이 없고 같은 브라우저를 사용하는 누구든 프로필을 열 수 있습니다. 민감한 영적 상담 기록이나 기도 노트 등을 클라이언트 저장소에 무분별하게 기록하지 않습니다.

## 권장 2단계: 계정 기반 동기화
- Firebase Authentication으로 Google 로그인 혹은 이메일 링크 로그인 구현
- Firestore: `users/{uid}/reading/{sessionId}` 구조로 읽음·즐겨찾기·마지막 열람 시간 저장
- `users/{uid}/settings/profile`: 서체 크기, 진도/트랙 설정 등
- Firestore Security Rules: `request.auth != null && request.auth.uid == uid` 검사
- 공개된 묵상 원고는 별도의 읽기 전용 정적 콘텐츠로 유지
- 로그인할 때 로컬 기록을 해당 UID 계정에 합치기; 완료 기록은 합집합, 마지막 열람 시각은 최신 값 우선
- 배포 전 실제 기기 2개 및 계정 2개로 분리 검증, 세션 로그아웃, 계정 데이터 삭제 정책 마련

## 편집과 발행
- 권위 자료는 Google Sheets/Docs 유지.
- 공개 체험판에 포함된 첫 5편은 정식 날짜별 발행과 구별.
- 검수된 원고만 배포 자료로 승격시키고, 미발행 DRAFT는 별도로 관리.
- Docs/Sheets의 편집 지위를 유지하면서 원고 배포 단일 데이터 원장으로 전환할 것.
